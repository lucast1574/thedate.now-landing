# Idioma automático

La landing usa la lista `Accept-Language` del navegador, reconoce español, inglés y portugués y recorre las preferencias antes de recurrir al español. Portugués utiliza copia de Brasil. Las URLs se conservan y no hay selector ni cookie de idioma.

La configuración de `src/lib/i18n/request.ts` resuelve el idioma en el servidor. El HTML, los metadatos, el contenido y la hidratación cliente comparten ese idioma. Utilizar `useTranslator` en componentes síncronos y `getTranslator` en funciones asíncronas del servidor. Los mensajes están incluidos en el build y no requieren una API externa en producción.

Mantener las mismas claves en `messages/es.json`, `en.json` y `pt.json`. Las claves corresponden a la copia española; los parámetros `{v0}`, `{v1}`, etc. conservan sus nombres y valores. Los nombres The Date y Save the Date no se traducen. No traducir IDs, URLs, tipos de schema ni valores usados para filtros; traducir sus etiquetas visibles.

Los ejemplos HTML del producto son snapshots estáticos propios, con variantes `workspace-preview-en.json` y `workspace-preview-pt.json`. Al regenerar el snapshot español, actualizar también sus dos variantes y comprobar el diseño. Los nombres y descripciones de las plantillas se localizan al presentar el catálogo; las imágenes de ejemplo conservan el contenido ilustrativo original.

Las pruebas cubren detección, respaldo, contenido del servidor, textos móviles, metadatos, integridad de catálogos y vocabulario de schema. Ejecutar `npm run check`.
